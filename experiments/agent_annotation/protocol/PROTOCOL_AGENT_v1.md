## 0. 任务定义

对每封邮件的每个句子，判断：**该句是否在实施钓鱼攻击的欺骗核心行为**
——提出骗局交易、抛出诱饵、索取信息/资金、把收件人引向欺骗性渠道、
施加与索取直接绑定的压力。**仅仅是铺垫、背景、前言、操作细节的句子
不是核心行为**（判例 9/10）。

每条标注两个字段：

| 字段 | 取值 | 说明 |
|---|---|---|
| `label` | `Y` / `N` / `?` | Y=欺骗核心句；N=非核心；?=语义无法判断（必须附理由） |
| `confidence` | `high` / `medium` / `low` | 对该判断的把握度 |

**label 与 confidence 的关系**：有倾向但把握不足时，给出倾向标签 +
`confidence: low`（不要逃进 `?`）；只有语义根本无法解读（乱码、截断）
才用 `?`。

## 1. Y 的判定标准（欺骗核心行为，满足其一）

只给行为定义，不给词表——判断靠语义与上下文：

1. **交易提议**：提出骗局式的交易、合作、提案（把好处/角色/资金安排
   摆到收件人面前）。
2. **诱饵**：抛出难以置信的好处作为钓饵——尤其是**报告巨额资金/存款/
   遗产/合同金额的句子**（判例 11：这是骗局的核心诱饵，不是背景铺垫）。
3. **索取**：索要凭据、账户、身份证明、支付信息、验证码、个人细节，
   或要求填表/回复个人信息。**注意（v1.3）**：当一句 pretext 把"账户/付款
   异常"与"须验证/提供信息才能继续"**绑定在同一句**时，它已在实施索取
   （如"须完成客户信息验证程序方可继续使用""因无法核实你的账户信息，
   付款未能到账"）→ **Y**，不因披着 pretext 外衣而降为 N（对照判例 9 的
   收窄）。
4. **欺骗性引导**：把收件人引向链接/附件/回复渠道**以完成上述索取或交易**
   （假验证、假登录、假领奖）。**注意（v1.3）**：**钓鱼链接/URL 本身就是
   引导的目标**——给出可点击的欺骗性网址、"点击 https… 取消删除/登录/
   验证"的句子 → **Y**（判例 5 收窄：只有与索取/交易无关的纯文本地址、
   合法官方域名引用才是 N）。注意判例 8/10 的其余排除情形。
5. **绑定式施压**：把不利后果**直接绑定在"不交出信息/资金/不点击"上**的
   压力句（"不付款就停用"）。**泛化的**恐吓、催促、保密要求不属于核心
   （判例 12）。

**多 Y 允许**；不强制选"唯一一句"；一封钓鱼邮件里大多数句子通常是 N。

## 2. N 的默认规则

以下一律 N（即使出现在钓鱼邮件中）：

- 签名档、免责声明、页脚、退订说明、版权声明
- 单独成句的礼貌问候与套话
- **纯虚假前言与背景铺垫（无索取）**：声称付款失败/系统升级/账户异常/
   收到投诉等 pretext 陈述**本身**、骗子的自我介绍与身份声称（判例 9）。
   **但（v1.3）**：若同句把 pretext 与"须验证/提供信息才能继续"绑定，则已
   构成 §1.3 索取 → **Y**，不适用本条。
- **合法操作/导航步骤（无欺骗性目标）**：教收件人如何在系统里点击标签页、
  选择账户、编辑字段的界面说明（判例 10）。**但（v1.3）**：若步骤给出钓鱼
  链接/URL 或指向欺骗性验证/登录，则是 §1.4 欺骗性引导 → **Y**，不适用本条。
- **纯产品广告/营销**：无冒充、无索取的推销句，即使使用了夸张或
  从众式营销话术（判例 12c）
- **整封邮件全部 N 是常见且合法的结果**：pilot 中人类标注员对约 40% 的
  邮件标了全 N（貌似合法的程序性通知、纯广告、只有铺垫没有核心行为的
  邮件）。不要"因为这是钓鱼语料"而强行找 Y——**每封邮件标完后问自己：
  如果全部是 N，是否真的找不到任何一句核心行为？**

## 3. `?` 的使用纪律

仅用于：乱码/编码损坏到无法理解句意（理由写 "garbled"）；截断/上下文
缺失到意图完全无法推断。每条 `?` 必须附理由。能用 Y/N + low confidence
表达的，不要用 `?`。

## 4. 核心纪律：判断意图，而非匹配关键词

- 禁止"数关键词"：句中出现敏感词汇**不自动等于 Y**——合法商业邮件同样
  包含它们；反之，含关键词的句子若只是前言/铺垫/操作步骤，仍是 N。
- **禁止查阅任何关键词词表/规则代码**（`phishingdata/kwords_stem.json`、
  `src/rules.py` 等）——那是被测系统的先验，看了即污染裁判独立性（铁律 2）。
- 判断标准始终是：这句话是否在实施 §1 的**核心行为**（对照 §5 判例）。

## 5. 判例（边界情形；8–12 为 pilot 校准判例，约束力等同 §1）

1. **主题行/标题句**：仅含标题、机构名、紧迫措辞或问候的开头句 → **N**
   （即使品牌冒充 + 紧迫词齐备）；只有当开头句**直接展开具体交易提议或
   索取**时才 Y。**v1.3 精确化**：标题句若**直接陈述**了①交易提议
   （"urgent business transaction investment proposal"）、②索取、或
   ③与账户绑定的威胁（"notification de restriction de l'accès au compte"
   ——账户被限制/停用），则该句已是核心行为的载体 → **Y**，不因"它在标题
   位置"而降为 N。仅"品牌名 + 紧迫词 + 问候"而无具体提议/索取/威胁时才是 N。
2. **泛称问候**：礼貌套话单独成句标 N；同句叠加交易提议/索取则整句 Y。
3. **粒度**：一句 = 任务文件给定的句子单元（按 `idx`），不拆分不合并；
   句内混合时以主导功能判定。
4. **长篇故事型骗局**：标 Y 的只有——交易提议句、金额诱饵句（判例 11）、
   索取信息/费用句、绑定式施压句；其余叙事（身世、背景、过程描述、
   合法性保证、泛化催促）全部 N。不要刷全 Y。
5. **引导句（v1.3 精确化）**：服务于假验证/假登录/假领奖的引导 → **Y**；
   **钓鱼链接/URL 本身 → Y**（给出可点击的欺骗性网址、"点击/继续到
   https… 取消删除/登录/验证"——URL 是引导的**目标**，不是被动引用）；
   只有**与索取/交易无关的纯文本地址、合法官方域名引用**才是 N；
   合法系统内操作步骤 → N（判例 10）。
6. **语言质量**：语法错误、拼写差本身不是证据。
7. **把握不足**：倾向明确但证据单薄 → 倾向标签 + `confidence: low`；
   语义无法解读 → `?`。
8. **【校准】貌似合法的程序性通知**：判断引导目标与要求性质——若邮件
   引导的是**真实官方渠道**且**未索取敏感信息/资金**（如域名注册信息
   核对、常规系统通知），按合法通知处理，可以整封 N。不要因为邮件来自
   钓鱼语料就预设它有罪。
9. **【校准】虚假前言 ≠ 核心行为（v1.3 收窄）**：**无索取的**纯 pretext 句
   ——声称"付款失败""服务器升级""检测到异常活动""收到第三方投诉"，以及
   骗子的自我介绍（"我是某银行职员/某部长"单独陈述）→ **N**。核心行为从
   "提议/诱饵/索取/引导/绑定施压"开始。**但**：若 pretext 在同句内**直接
   绑定一个索取或验证要求**（"须完成客户信息验证程序方可继续使用""因无法
   核实你的账户信息付款未到账，请提供…"），它已在实施 §1.3 索取 → **Y**。
   判据：这句话除了制造借口，是否**同时**在向收件人要信息/要其验证？是→Y。
10. **【校准】操作步骤 → N（v1.3 收窄）**："点击某标签页""选择某账户"
    "登录某管理器"之类**指向合法界面、无欺骗性目标**的操作说明 → N。
    **但**：若操作步骤**给出钓鱼链接/URL** 或指向**欺骗性验证/登录/领奖**
    （"点击 https… 取消删除""继续到 8594 登录你的 iTunes ID"），则是
    §1.4 欺骗性引导 → **Y**（见判例 5）。
11. **【校准】金额诱饵 → Y**：叙事型骗局中报告巨额存款/遗产/合同金额/
    分成比例的句子是"好到不真实"的诱饵本身 → **Y**（人类锚定：这类句子
    人类标 Y 而 agent v1.1 误标 N，是最主要的反向分歧）。
12. **【校准】泛化压力 vs 绑定施压**：
    a. 把后果直接绑定在"不交钱/不给信息/不点击"上的句子 → Y；
    b. **泛化的**一般性恐吓、催促回复、要求保密、奉承（"听说你很可信"）
       → N。所谓"泛化"= 未绑定具体索取、也未构成冒充性欺骗前提的笼统
       紧迫（"尽快回复""这是优先消息"）；
    c. 纯产品推销的从众/好奇话术（"为什么人人都在谈论 X"）→ N。
    **v1.3 边界**：判例 12b 的 N **不覆盖**两种情形——① 后果已绑定到
    "不验证/不提供信息"（→ 12a，Y）；② "账户被限制/停用"的声称是
    **冒充某机构、为骗取凭据铺垫的欺骗性前提**（尤其出现在标题/开头句，
    如"notification de restriction de l'accès au compte PayPal"）→ 按
    判例 1 v1.3 ③ 处理，**Y**。只有与具体索取/欺骗前提无关的笼统停用
    恐吓才是 N。

## 6. 每封邮件标注流程（模拟人工标注员思维）

1. **通读整封邮件**全部句子。
2. 写一句场景假设（发件人声称是谁 / 场景 / 要求收件人做什么），
   以 `[scenario]` 前缀附在 idx=0 句 reason 中。
3. **先做整封预判**：这封邮件有没有 §1 的核心行为？（判例 8：可能是
   貌似合法的通知；判例 12c：可能是纯广告。）没有 → 全 N。
4. 逐句判断：该句是核心行为（Y）、前言/铺垫/操作/套话（N），
   还是无法解读（?）。给 confidence；Y 和 ? 必附 ≤20 词 reason。
5. **自查（双向；轮 2 显示 v1.2 曾从紧过正，重点防漏标）**：
   - **防漏标（v1.3 重点）**：钓鱼链接/URL 句（判例 5）、与验证/索取
     绑定的 pretext 句（判例 9 但书）、直接展开提议/索取/账户威胁的标题句
     （判例 1 v1.3）、金额诱饵句（判例 11）——这些是否被误降为 N？
   - **防从宽**：每个 Y 能否指出 §1 的哪一条核心行为？有没有把**无索取的**
     纯 pretext（判例 9）、**无欺骗目标的**合法操作步骤（判例 10）、
     泛化压力（判例 12b）误标 Y？
   - 判据始终是"这句话**自身**在实施哪一类核心行为"，不是它出现在邮件的
     什么位置（标题/正文/结尾）。

## 7. 输出格式

```json
{
  "annotator": "<pass 名，如 agent_pass_a>",
  "batch": "<pilot_30_blind 或 production_chunk_N>",
  "exported_at": "<ISO 时间>",
  "n_emails": 30,
  "annotations": [
    {
      "email_id": 4860,
      "sentence_idx": 0,
      "sentence_text": "...",
      "label": "Y",
      "confidence": "high",
      "reason": "[scenario] ...; §1.1 transaction proposal"
    }
  ]
}
```

- 每个 (email, sentence) 恰好一条记录，不遗漏、不重复。
- `stratum` 字段留空或省略（盲态；评分脚本回填）。
- `email_id` = 任务文件的 `email_idx`；句子文本原样复制。
- reason 中引用判例/标准编号（如 §1.3、判例 9），便于仲裁与审计。

## 8. 汇总与仲裁（流程控制方执行，非单 pass agent 职责）

- 3 个独立 pass 逐句取多数（≥2 票）为初步 gold；无多数 → 仲裁 agent。
- confidence=low 占比单列统计。
- κ 计算复用 `src/annotation_agreement.py`；门槛见
  `scripts/score_agent_calibration.py`（v1.2 起 G1 基线调整为 0.50 +
  parity 条款，理由见 CALIBRATION_LOG.md）。
